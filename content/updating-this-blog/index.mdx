The blog is deliberately file-based. An article is a folder containing one `index.mdx` file and, when useful, the images that belong to it. There is no database or publishing dashboard to keep alive. The repository is the archive, and a production build turns every published note into a fast HTML page.

<Callout title="The short version">
  Create a folder in `content`, add an `index.mdx`, fill in its metadata, write the article, and rebuild the site. The blog index discovers the new folder automatically.
</Callout>

## 1. Create the article folder

Use a lowercase, hyphenated name. That folder name becomes the public URL:

```text
content/
  writing/
    a-new-field-note/
      index.mdx
      route-sketch.webp
```

This example will appear at `/blog/a-new-field-note`. Once an article has been shared, avoid changing its folder name: doing so changes the URL.

## 2. Add the metadata

Every article exports the same small record near the top of the file:

```js
export const article = {
  title: 'A new field note',
  description: 'One useful sentence that explains what the note contains.',
  publishedAt: '2026-08-12',
  readingMinutes: 5,
  tags: ['Design', 'Process'],
}
```

The date uses `YYYY-MM-DD`, which keeps chronological sorting predictable. The description appears in search results and page metadata, so it should make sense without the title. Tags are case-sensitive labels; reuse an existing spelling when a topic already exists.

## 3. Write with Markdown

Normal Markdown provides the editorial structure: headings, paragraphs, lists, links, quotations, and fenced code blocks. Add a language after the opening fence so code remains meaningful even before visual highlighting is applied.

```tsx
export function SmallExample({message}: {message: string}) {
  return <p>{message}</p>
}
```

Keep one `#` heading out of the article body. The page layout already uses the article title as the document’s first-level heading, so sections inside the MDX file begin with `##`.

## 4. Insert an image

Images can live beside the article or reuse an existing public asset. Import a local image, then pass it to the editorial `Figure` component:

```mdx
import routeSketch from './route-sketch.webp'

<Figure
  src={routeSketch}
  alt="A hand-drawn route crossing a contour map"
  caption="The route sketch used while planning the article."
/>
```

The alternative text describes the information in the image. The caption can add context, but it should not repeat the alternative text. Imported images include their dimensions automatically, allowing the browser to reserve the correct amount of space before they load.

Use images when they explain, document, or change the rhythm of the article—not simply because a long page feels empty.

## 5. Use the small component vocabulary

MDX also understands the components registered in `mdx-components.tsx`. The initial vocabulary stays intentionally small:

- `Figure` adds responsive images, captions, and optional credits.
- `Callout` separates a practical warning or summary from the main argument.
- fenced code blocks present code without requiring a browser-side editor.

That constraint keeps articles consistent and makes a future content migration possible. Add a new component only after at least one real article needs it.

## 6. Review and publish

Start the local site and read the article as a visitor would:

```bash
npm run dev
```

Check the page on a narrow phone-sized window as well as a desktop window. Confirm the title hierarchy, image crops, links, keyboard focus, code overflow, and the article’s appearance in search and tag filters. Then run the production build:

```bash
npm run build
```

Publishing the repository deploys the newly generated page. Because articles are produced during the build, readers receive static HTML with minimal JavaScript; the interactive JavaScript on the archive is limited to search, filtering, and sorting.

<Callout title="Before publishing">
  Read the description on its own, verify the date and tags, provide useful alternative text for every image, and make sure no draft notes or private paths remain in the article.
</Callout>
